# 性能分析与加速路线（仿真与前向管线）

基准对象：全 CNS 导出（45 导、10.5 s 生物学时间、21,000 步、
~111k 神经元 / ~3M 突触态 / ~42 万投影边偶极）。实测总耗时
**8–10 min**，构成见下。

硬件背景：本机有 NVIDIA RTX 4060 Ti（16 GB；FP32 ≈22 TFLOPS，
带宽 288 GB/s）——GPU 路线现实可行，需 `pip install cupy-cuda12x`。

---

## 1. 耗时解剖（实测锚点）

| 阶段 | 耗时 | 占比 | 计算性质 |
|---|---|---|---|
| 头皮核构建（Legendre 级数，45 电极 × ~30 万边偶极） | 351–361 s | ~55% | 元素级级数求和，完全并行，numpy 单线程 |
| 生物学仿真循环（21,000 步 × 0.5 ms） | ~2–4 min | ~25% | 每步：3M 突触态衰减 + 机制板层电流 + LIF + OU；numpy 小数组逐步循环 |
| 前向核应用（每 1 ms 一次 GEMV） | ~1–2 min | ~12% | (45 × 42 万) coef @ y，float64 ≈ 152 MB——**内存带宽受限**，10,500 次 ≈ 1.6 TB 内存流量 |
| 背景 EEG / 组装 / 写盘 | < 1 min | ~8% | — |

## 2. 瓶颈结论

1. **核构建**：并行度天然（电极独立），只是 numpy 没用上多核/GPU；
2. **生物学循环**：单步工作量很小（几 MFLOP），成本在 Python 调用
   开销与缓存不友好——时间轴本质串行，不能并行化时间，只能加速
   单步；
3. **核应用**：GEMV 是带宽受限——算力无用武之地，关键是**少搬数据**。

## 3. 路线 A：CPU 结构优化（无 GPU、无精度风险，半天工作量）

| 项 | 做法 | 预期 |
|---|---|---|
| A1 运行时边偶极池化 | 42 万边偶极聚类成 3–5k 代表偶极（权重=边数；前向核在位置空间光滑，既有 300k 子采样+reweight 机制已验证 <1% 误差）→ 每次记录的 GEMV 变为 45×5k（1.4 MB） | 核应用 100×↓（~90 s → ~2 s） |
| A2 核构建多进程 | 45 电极相互独立 → multiprocessing(8) | 361 s → 60–90 s |
| A3 float32 系数 | 带宽减半 | 应用再 ~2× |

**关键红利（A1 的延伸）**：生物学仿真 y(t) 与电极**无关**——池化后把
Y(t)（5k × 10,500 float32 ≈ 210 MB）落盘一次，45/64/128/241 每套
电极配置 = 一次小型 GEMM（秒级）。多配置导出从"每套一次全量"变为
"一次仿真 + N 次秒级投影"。

## 4. 路线 B：GPU（CuPy，RTX 4060 Ti 完全够用）

| 项 | 内容 | 预期 | 风险 |
|---|---|---|---|
| B1 核构建 CuPy 化 | 代码已完全向量化，CuPy 近乎 drop-in；**必须 FP32**（消费卡 FP64 为 1/64 吞吐） | 351 s → 10–30 s | 低（系数误差需对拍，预期 <0.1%） |
| B2 核应用 GPU 常驻 | coef 驻显存 + 每记录传 y（3.4 MB） | 全导出 ~15 s | 低；但 A1 之后此阶段已非瓶颈 |
| B3 生物学循环全 GPU | 状态量（3M 突触 ×8B ≈ 24 MB）轻松进显存；21k 步 × ~10–30 个 kernel 的**发射开销**是主项（CUDA Graphs / kernel 融合可压） | 仿真循环 ~2–3 min → ~10–20 s | **高**：ExponentialSynapses/机制板层/递质门全部重写，且必须与 CPU 校准轨迹逐点对拍 |
| B4 Numba/Cython 热点（替代 B3 的折中） | 只 JIT 突触衰减/机制电流/投递 | 单步 5–20× | 中 |

## 5. 推荐组合

- **近期（半天）**：A1 + A2 + A3 → 45 导导出 12 min → **2–3 min**，
  且 64/128/241 导的边际成本降到秒级；
- **中期（1 天）**：B1 核构建 GPU → 全导出 ≈ **1 min**；
- **远期（3–5 天，按需）**：B3 全 GPU 仿真 → **秒级**；仅当 256+ 导
  或大规模参数扫描成为日常时才值得。

## 6. 红线与验证

- 任何加速不得改变校准动力学：以现有 45 导导出为基准做轨迹对拍
  （阈值：头皮电位误差 <0.1 μV 或 <1%）；
- FP32 化记录在案；SNR 数字（当前 0.15 μV @FC6，demo 视频）对幅值
  缩放敏感，加速前后必须复算；
- CuPy 需匹配 CUDA 12.x（驱动 591.86 ✓），`pip install cupy-cuda12x`。

## 7. 实施进展（路线 A 已落地）

smoke 规模实测（17 电极 × 35.2 万偶极，400 ms 协议，16 逻辑核）：

| 项 | 前 | 后 | 说明 |
|---|---|---|---|
| 核构建 | 29 s | **5–6 s** | `four_sphere_rows`：fg 表按头几何缓存（原来每电极每重复算一遍 60 个 7×7 解）；运行积 R_n=(r0·re)^n 替代每阶 pow（~1.3×）；45/17 电极线程池并行（numpy 元素级运算释放 GIL，16 核 ~5.8×） |
| 前向应用 | 逐记录 f64 GEMV | **CHUNK=256 行主序缓冲 + f32 GEMM** | 每记录每组的 `coef@y`（带宽受限）合并为每次 flush 一个 GEMM；记录按行连续写入 ybuf，flush 用转置视图零拷贝喂 BLAS。smoke 400 记录 23 s→17 s；全量 10,500 记录处收益更大（原估 1–2 min → 秒级） |
| 精度对拍 | — | **L2 逐位一致，max rel 4.8e-7** | 新旧路径 phi_scalp 全数组对拍；偏差恰为 f32 系数量级（<1% 红线 20 倍裕度）。单测：CSF 合并回归 <1e-8、参考级数 <1e-10、批量/单电极逐位一致（tests/test_four_sphere_rows.py） |

顺带修复的存量 bug（均由小规模迭代暴露）：

1. `record()` 内 `pool_err = ...` 赋值使闭包变量变局部 → 默认（非
   `--pool`）导出路径第一次记录即 `UnboundLocalError` 崩溃；
2. 池化精化重试时 `acc_s` 不清零 → 失败重试后头皮电位整体翻倍；
3. `snr_metrics` 窗口 [1500, 4500) 超出短记录长度 → smoke 崩溃
   （现按 n_field 跳过，页面端本就有空值保护）。

全量规模实测（45 导 / 10.5 s / 21,000 步 / 全 CNS 5 区域 /
**123 万投影偶极**）：

| 阶段 | 旧代码（估算） | 新代码实测 | 说明 |
|---|---|---|---|
| 核构建 | 15–20 min | **68 s**（~15×） | 16 组 × 45 电极批处理 + 线程池 |
| 生物学循环 + 前向应用 | ~60–75 min | **47 min** | 冗余 edge_currents 调用删除（ker 组 4 次/记录 → 1 次）+ f32 GEMM；剩余成本是每记录 1 次的 123 万边电流计算与突触衰减——**路线 B3/B4 的目标** |
| 精度对拍 | — | **头皮 max 0.001 μV（0.092% 峰值），corr 1.000000；phi 逐位一致** | vs 旧代码全量基线；f32 系数量级，红线（<0.1 μV 或 <1%）内 100× 裕度 |

**重要教训（2026-09 事故）**：`regions_default` 只开
`visual_bilateral`（vpn_central 等默认关）。重导出时漏传
`--regions visual_bilateral,vpn_central,ol_rest,central_brain,vnc`
会静默产出"视觉区 only"的数据：页面只剩视叶点云，且因 RNG 消耗流
不同，头皮轨迹 vs 全 CNS 基线逐点去相关（峰值差 33% 但 corr 结构
正常）——极易误判为加速改动了物理。现导出开始即打印 ON/OFF 区域
清单并把 `meta.regions` 写进 viz_data.json。

调试设施：导出结束把 `phi_scalp`（×1.7 后）与 fly-head `phi` 存至
输出目录 `_debug_phi_scalp.npy` / `_debug_phi.npy` 作为 A/B 基线；
控制台打印各阶段耗时、每组偶极数、缓冲区大小与 L2 校验和。
