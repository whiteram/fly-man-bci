# bci/sleep2 — 上行态维持机制的鉴定（睡眠探针后续）

机制 14 遗留问题：sz_l 点火后 10.5 µV 上行态平台**与 CEN_C 的
STD 门控无关**——当时的推断是"维持电流不走复发"。本研究用
`--gain-scale` 逐个零化候选通路做归因，**推翻了该推断**：

| 臂 | 零化 | 点火 µV | 平台 µV | 平台上的活跃 class |
|---|---|---|---|---|
| base | — | 10.35 | 10.35 | KC 74, MBON 395, ALPN 215, DAN 43 Hz |
| **noCEN_C** | CEN_C ×0.02 | **1.39** | **1.39** | **全部 <1 Hz（塌缩）** |
| noCEN_R | OLR→CEN ×0.02 | 10.30 | 10.37 | 同 base |
| noOLR_V | 视觉核→OLR ×0.02 | 10.62 | 10.63 | 同 base |
| noCEN_V | 视觉核→CEN ×0.02 | 10.25 | 10.25 | 同 base |
| noORN_C | ORN→CEN ×0.02 | 10.35 | 10.35 | 同 base |

**结论：上行态维持者 = CEN_C 复发（全增益 0.004）；一切前馈通路
（OLR/视觉/ORN）都不是。** 机制 14 的"U 无关性"需重新解读：不是
"维持不走 CEN_C"，而是**当时参数化的 STD 门没有咬住维持电流**
（候选原因：τ_rec 恢复太快，在上行态时间尺度内资源回满；或所扫
U 范围在高发放率下的稳态资源仍高）。睡眠双稳态的可行路径因此
明确：需要能在秒-十秒尺度上耗竭的慢变量（如 τ_rec ≥ 5 s 的资源
门，或自适应 i_base），而非快 STD。

## 用法

```bash
conda activate ffbm
python bci/sleep2/acquire.py     # 6 × 20 s
python bci/sleep2/analyze.py
```
