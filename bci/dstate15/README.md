# bci/dstate15：重暴露痕迹检验——治愈态=幼稚态

dstate14 留下最后一块拼图：增益治愈后的网络是「真幼稚」还是携带
敏感化/不应期痕迹？同链三事件设计（新 `--gain-schedule` 运行时
旗标）：脉冲 1（0.3 s）成锁 → 30 s 增益 ×0.5 溶解 → 45 s 增益
×2.0 恢复（0.001→0.002）→ 50 s 脉冲 2 重暴露。

## 结果

| 读出 | trace_test | restore_only（无脉冲 2） |
|---|---|---|
| L1（首次成锁延迟） | **0 ms** | 0 ms |
| 溶解后 [40,44] s | 0 Hz | 0 Hz |
| 恢复后 [46,50] s（无脉冲） | 0 Hz（无自发再锁） | 0 Hz |
| **L2（重暴露成锁延迟）** | **0 ms** | — |
| 尾段 [56,62] s | **20.0 Hz（再锁持续）** | 0 Hz |

**判决：无痕迹**——治愈后的网络对同一暴露的响应与幼稚态逐位同
级（0 ms 即刻成锁、尾段同样持续）；恢复增益但无脉冲则保持暗态
（锁是脉冲触发的吸引子，窗内无脉冲不成锁）。

## 附带工程发现（诚实记录）

首版 dstate15 的 "restore" 写成 ×1.0——乘法语义下是无操作
（0.001 仍是 0.001），导致「脉冲 2 不再成锁」的假阳性读数，一度
疑似不应期痕迹。经三段探针（旗标无害 / chem 条目无害 / 复跑
复现）+ 波形验证后定位为语义错误。**教训：--gain-schedule 的
因子是乘在当前值上，恢复要用补偿因子（×0.5 的恢复 = ×2.0）**。
读出器同批修正：1-ms 瞬时率的「连续 500 ms>15 Hz」判锁过严
（锁的瞬时率 ~18% 时间跌破均值），改为 1-s 滑动均值。

语义终章：**静默锁的完整生命周期**——一次越阈暴露成锁（dstate7/10
锐边）→ 动力学探针不可出、增益下调即解（dstate14，无迟滞）→
治愈态行为幼稚、可再暴露再固化（本弧线）→ 循环无疲乏（至少
一次循环内）。锁是状态，不是伤疤。

诚实边界：单种子；一次循环（多循环疲劳未测）；「0 ms 延迟」
的分辨率是 1 s 滑窗（亚秒差异不可辨）。
