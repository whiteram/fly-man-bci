# bci/sleep7：平台态压制响应的底物定位

sleep4–6 留下的问题：平台态的「响应封顶 45%」由什么承载？
（资源已排除——sleep6 测得 d 恢复 97.6%。）本弧线纯分析
sleep5 既有 1-ms 群体速率文件，零新采集。

## 增量分解：p2 点火脉冲相对平台基线

对 sleep5 延迟点（D=35/50/80 s，同一剂量），比较平台基线
[D−8, D−2] s 与 p2 窗口 [D, D+5] s 的逐群体增量：

| 增量（Hz） | D=35 | D=50 | D=80 | p1（幼稚网络）参考 |
|---|---|---|---|---|
| ALPN | +1.7 | +1.0 | +0.7 | 120（基线 0） |
| KC | +6.1 | +6.2 | +6.2 | 31（基线 0） |
| **MBON** | **+60.1** | +62.1 | +59.3 | ~150（基线 0） |
| DAN | +6.0 | +6.0 | +5.9 | 11.9 |

三个定位：

1. **AL 引擎被钉死**：同一点火驱动在幼稚网络把 ALPN 推到
   120 Hz，在平台态只增 +0.7~1.7 Hz（其 40 Hz 自持水平的
   ~2%）——AL 回路（PN↔LN）钉在自己的自持不动点上，对中央
   驱动几乎无响应。
2. **PN→KC 腿失效**：ALPN 40 Hz 自持却只养出 KC 0.1 Hz 基线、
   脉冲也只 +6 Hz——与 condit3 的「PN→KC 被 CEN_C 工作点压制」
   同源（ALK 行在 CEN_C 内，即便 no_cen_damp 0.004 也不通）。
3. **MBON 读出腿反而响应强烈**：+60 Hz = 自身基线（5 Hz）的
   13×——读出没有失败；R_mbon≈0.41 的「封顶」是 p1 大瞬态
   分母效应 + 上游两级失效的复合，**不是 MBON 或资源的问题**。

## 结论：压制底物 = AL 钉死 + KC 腿失效

平台态的响应封顶由两个上游机制承载：(i) AL 引擎钉死在其自持
不动点（与 dstate 系列的「AL 局部引擎」同一底物——两个被压制
状态共享机制的证据再加一条）；(ii) KC 级联失效（CEN_C 内
ALK 腿）。资源（sleep6）、MBON、抑制（本模型该 regime 无功能
抑制）均非限制者。「网络态压制」至此在模型层完全定域。

诚实边界：分析基于单种子既有文件；「KC +6 的驱动来源」未
进一步定位（中央直驱 vs ALPN 残余）；AL 钉死的分子实现（哪个
回路参数）未拆。
